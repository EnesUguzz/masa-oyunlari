# Okey E2E (Playwright) (2c) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** End-to-end browser tests (Playwright) proving the full stack: solo-vs-bots gameplay and two-browser lobby sync.

**Architecture:** Root `@playwright/test` + `playwright.config.ts` (starts `pnpm dev` as a webServer) + `e2e/` specs using role/text/testid selectors. Structural assertions only (deal is random). Two small `data-testid`s added for robust selection.

**Tech Stack:** Playwright, the running React+Vite client and Socket.IO server.

**Spec:** `docs/superpowers/specs/2026-06-16-okey-e2e-design.md`

---

## Conventions
- `pnpm test:e2e` runs Playwright (separate from `pnpm test` unit tests). The eslint config is NOT type-aware and only forbids `any`/`console` — so e2e/config files just must avoid those (they do); no eslint-ignore needed.
- E2E uses structural assertions (counts, turn, screen transitions), never specific tiles.
- Playwright auto-waits; do NOT add fixed sleeps.

## Task 2: Solo-vs-bots full-flow E2E

**Files:** Create `e2e/solo-vs-bots.spec.ts`.

- [ ] **Step 1: Write the test:**
```ts
import { test, expect } from "@playwright/test";

test("a single human fills with bots, starts a game, and plays a move", async ({ page }) => {
  await page.goto("/");

  // nickname -> lobby
  await page.getByRole("textbox").fill("Ben");
  await page.getByRole("button", { name: "Devam" }).click();

  // create room
  await page.getByRole("button", { name: "Yeni Oda Kur" }).click();
  await expect(page.getByTestId("room-code")).toBeVisible();
  await expect(page.getByText(/\(1\/4\)/)).toBeVisible();

  // fill with bots -> 4/4
  await page.getByRole("button", { name: "Botlarla Doldur" }).click();
  await expect(page.getByText(/\(4\/4\)/)).toBeVisible();

  // start the game (default config)
  await page.getByRole("button", { name: "Oyunu Başlat" }).click();

  // table appears; you are the 22-tile starter, draw phase
  await expect(page.getByText(/Senin elin \(22/)).toBeVisible();
  await expect(page.getByRole("button", { name: /Desteden çek/ })).toBeVisible();

  // draw -> 23 tiles, act phase
  await page.getByRole("button", { name: /Desteden çek/ }).click();
  await expect(page.getByText(/Senin elin \(23/)).toBeVisible();

  // select a hand tile and discard
  await page.locator('[data-testid="hand"] button').first().click();
  await page.getByRole("button", { name: "At", exact: true }).click();

  // bots auto-play; the turn returns to you (draw button visible again)
  await expect(page.getByRole("button", { name: /Desteden çek/ })).toBeVisible();
});
```

- [ ] **Step 2: Run it:**
```bash
pnpm test:e2e e2e/solo-vs-bots.spec.ts
```
Expected: 1 passed. If a selector misses (e.g., the "At" button is matched ambiguously or the draw label differs), inspect the actual rendered text via `pnpm test:e2e --debug` or a `page.pause()`, and adjust the selector to match the real UI text (do NOT change app behavior; only fix the selector). The button labels are: "Desteden çek (N)", "Yerden al", "Gruba ekle (...)", "Perlerle Aç", "Çiftlerle Aç", "Yeni Per", "İşle", "At". The discard button's accessible name is exactly "At".

## Task 3: Two-browser lobby-sync E2E + final verification

**Files:** Create `e2e/two-browsers-lobby.spec.ts`.

- [ ] **Step 1: Write the test** (two isolated browser contexts so localStorage tokens don't collide):
```ts
import { test, expect } from "@playwright/test";

test("two browsers in the same room see each other", async ({ browser }) => {
  const ctxA = await browser.newContext();
  const ctxB = await browser.newContext();
  const a = await ctxA.newPage();
  const b = await ctxB.newPage();

  // A: nickname -> create room -> read the code
  await a.goto("/");
  await a.getByRole("textbox").fill("Alice");
  await a.getByRole("button", { name: "Devam" }).click();
  await a.getByRole("button", { name: "Yeni Oda Kur" }).click();
  const code = (await a.getByTestId("room-code").innerText()).trim();
  expect(code.length).toBeGreaterThan(0);

  // B: nickname -> join with the code
  await b.goto("/");
  await b.getByRole("textbox").fill("Bob");
  await b.getByRole("button", { name: "Devam" }).click();
  await b.getByRole("textbox").fill(code);
  await b.getByRole("button", { name: "Katıl" }).click();

  // both browsers now show 2 players, each seeing both nicknames
  await expect(a.getByText(/\(2\/4\)/)).toBeVisible();
  await expect(b.getByText(/\(2\/4\)/)).toBeVisible();
  await expect(a.getByText("Alice")).toBeVisible();
  await expect(a.getByText("Bob")).toBeVisible();
  await expect(b.getByText("Alice")).toBeVisible();
  await expect(b.getByText("Bob")).toBeVisible();
  // each sees "(sen)" on their own row
  await expect(a.getByText(/Alice.*\(sen\)/)).toBeVisible();
  await expect(b.getByText(/Bob.*\(sen\)/)).toBeVisible();

  await ctxA.close();
  await ctxB.close();
});
```
- [ ] **Step 2: Run it:**
```bash
pnpm test:e2e e2e/two-browsers-lobby.spec.ts
```
Expected: 1 passed. The `(sen)` rows render as `<li>Alice 👑 (sen)</li>` (owner) and `<li>Bob (sen)</li>`; the regexes `/Alice.*\(sen\)/` / `/Bob.*\(sen\)/` match. Adjust only if the real markup differs.

## Notes for the implementer
- **Environment:** `pnpm exec playwright install chromium` downloads the browser once. The webServer config starts `pnpm dev`; first start is slow (Vite + tsc) — the 120s timeout covers it. If the dev server is already running, Playwright reuses it.
- **Selectors:** prefer `getByRole`/`getByText`/`getByTestId`. The app UI is in Turkish; match the exact button/label text. Only structural assertions (counts, turn, screen) — never specific tiles (deal is random).
- **No app behavior changes** beyond the two `data-testid`s. If a selector fails, fix the selector, not the app.
- **Out of scope:** full hand-finish E2E, reconnect E2E, CI wiring, visual snapshots.
